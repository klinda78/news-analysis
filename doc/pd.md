需求说明书 - 多信息源事件识别项目

## 一、背景与目标

随着金融市场和商业环境日新月异，及时捕捉和深入分析市场事件成为实现投资盈利的关键，     
本项目旨在通过高度流程化的数据抓取、处理与初步聚焦，从指定数据源中提炼出有价值的“候选事件” ，为专家的投资决策和市场机会提供依据。  
系统从多种数据源（如新闻、社交媒体、电商平台、政府政策等)，通过及时关注重要候选事件的演化，服务于event_driver_trading。  
帮助把握重要的交易时机。   

NOTE:  请注意本项目不是要建造一个多专家系统，而是完成这个系统的基础层：fetch-data-layer。

-- 硬约束  
```
在有限硬件条件CPU AMD r5 2200u的条件，运存16g的条件下保证项目可行。
非高频，最快10分钟获取某些数据
目标源数据可设置active 开启，inactive 关闭，以便合理抓取数据，降低系统压力，提高运行效率
-- 目标抓取&初步筛选: 
通过系统化的数据抓取与清洗，从指定一个或者多个信息源中提取市场事件。
事件驱动: 根据捕获到的事件，自动化识别可能的市场机会。
```
-- 协作
```
数据必须格式化: 以便之后可以提供给多专业领域的专家团队继续分析，用来支持和优化投资决策。
```
-- 优势
```
自动化: 系统自动化抓取、清洗、识别及机会分析，减少人工干预。
```
## 二、项目架构

系统整体架构分为三个主要部分：
```
-- 数据源抓取与清洗: 收集和处理来指定数据源的数据。
-- 事件驱动分析: 从数据中去噪，过滤 聚类，得到候选事件，例如500条信息，压缩出5-10条，进行机会识别。
（后续：格式化的数据将移交给 专家系统: 投研分析师、新闻监控专家、内容运营专家），进一步分析。
```
## 三、功能需求

### 1. 数据源与信息抓取

1.1 数据源分类与标签

系统需从多种数据源中抓取信息，主要包括以下几类：
```
新闻与社交媒体：Twitter、Reddit、行业新闻网站。
政府和官方公告：包括政策变动、气候变化、医疗公告等。
电商平台与消费行为：淘宝、京东、Amazon等电商平台的行为数据。
技术趋势与深度分析：YouTube、Medium、行业论坛等。
预测市场：预测市场网站热门事件
资本流动：资本现金流向。
```
1.2 数据抓取方式

每个数据源将根据其特点选择合适的抓取方式：

Web抓取：通过API接口抓取或直接抓取网页内容（包括解析CSS、XPath）。
第三方API：如Twitter API、新闻网站API等。
浏览器模拟抓取：使用浏览器插件（如Claw）抓取和解析动态网页内容。
OAuth认证：从需要认证的API中抓取数据（如社交媒体平台的API）。

### 2. 数据处理与事件识别

2.1 数据过滤与清洗
对抓取到的数据进行初步清洗，剔除噪声信息。  
根据事先定义的market_mapping，envent_Phase_status 筛选出符合市场机会定义的事件类型。  

2.2 事件抽取,过滤与分类

从原始数据中抽取具体的市场事件。事件类型包括但不限于：
```
政策变动：如政府宣布的财政刺激措施、利率调整等。
供应链中断：如企业或国家面临的供应链问题，产能短缺等。
技术突破：新技术或新产品的发布，可能影响市场。
资本流动：股市、期货市场的资金流动。
危机事件：例如自然灾害、突发公共卫生事件等。
```
2.3 事件映射与评分
```
将识别的事件根据其重要性、时间敏感性、资本相关性、趋势潜力等多个维度进行评分和分类。
```
### 3. 方案要考虑后续的协作

3.1 任务分发与协作
```
新闻监控专家：本项目的主要使用者，通过项目最终输出符合要求的舆论事件。
任务分发：候选事件，将被派发给不同agent进行分析。
a.投研分析师：分析该事件对资产的影响，判断是否构成投资机会。
b.内容运营专家：评估事件在社交媒体上的传播效果，判断是否有病毒传播的价值，以及事件未来的发展趋势。
c.代码调教高手：迭代，维护本项目的稳定性，维护长期知识库和skills，维护代码的稳定性影响。
```
3.2 为后续的专家系统提供数据基础  
各专家基于事件的相关性、重要性、潜在影响等，提供相应的分析与建议。最终形成市场机会的决策支持报告，供系统或投资者参考。

### 4. 记忆与历史数据更新   

4.1 事件记录与历史数据  

系统将原始数据集，候选事件和决策信息记录到memory/目录下，以便后续回溯和决策。  
每日总结与回顾当前的事件记录，并将重要信息转入长时间记忆库（MEMORY.md）。  

4.2 内存更新与周期性审查  

系统每隔一段时间通过heartbeat任务进行内存更新，清理过时信息，并总结提炼出有效的长期记忆。  

## 四、理解完整的多专家协作系统的workflow
对专家系统工作流的 完整理解有助于我们了解当前项目在系统中所处的位置，才能得到合理的实现方案。  
```
1. 数据收集与过滤
根据指定数据源, 系统定期或按需抓取数据源，过滤无关信息。
2. 事件识别与分类
根据预定义的事件模型，自动抽取并分类市场事件。
得到候选事件，存档到memory目录\event_xxxxxx.j
3. 任务派发
候选事件转交子专家（投研分析、新闻监控、内容运营等）进行进一步分析。
4. 机会判断与行动
每个专家给出反馈后，系统根据分析结果判断是否构成市场机会，若是，则生成投资建议或操作指令。
5. 持续学习与记忆更新
每次事件处理后，系统将对内存进行更新，总结得失，不断完善事件识别模型。
```
## 五、技术要求与接口

1. 技术架构
```
数据抓取：基于Node.js与axios，结合第三方API、Web抓取、OAuth认证、浏览器模拟抓取等方式。
事件识别：采用python完成初步清洗，可包括机器学习模型，可以考虑通过cheap embedded llm 分析抓取的数据。
专家协作与任务调度，基于openclaw架构：基于工作流引擎，自动化分配任务给不同领域的专家。
2. 关键接口
数据源管理：可配置指定数据源，方便管理不同来源的数据。
内容解析接口：从原始数据得到标准格式的数据
事件分类与评分(参数可调)：提供对事件进行分类、评分的接口。
读取数据接口：初期可以直接用jsonl保存，快速检测方案可行性。后期可以提供数据读取的接口。
```

## 七、总结
本项目通过固定的业务流程，实现以下目标
```
1. 从预置的数据源中提取有价值的候选事件，为后续投研师的工作，提供客观数据基础。
2. 通过部署使用本项目，将它与其他多专家系统合理结合，不仅能帮助投资者抓住市场机会，还能实现高效、持续的自动化运营。
3. 本项目配合openclaw的多专家agent系统，对事件做进一步的deep-insigne分析，可以实现对交易机会的捕捉和识别。
```
